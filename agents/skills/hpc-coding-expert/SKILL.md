# HPC コーディング・最適化ガイドライン

本スキルは、CPU/GPUを問わず、並列計算プログラムの限界性能を引き出すためのメモリ配置設計および最適化手法の知見をまとめたものである。コードの実装や最適化、およびコードレビュー時に必ず参照すること。

## 1. メモリレイアウト設計: SoA (Structure of Arrays) の原則

HPCにおける数値計算（粒子法、ステンシル計算など）では、特別な理由がない限り **SoA (Structure of Arrays)** 構造を採用する。

### なぜ SoA なのか？

| 観点 | AoS (Array of Structures) | SoA (Structure of Arrays) |
|---|---|---|
| **メモリ上の配置** | `[x, y, z, vx, vy, ...], [x, y, z, ...]` | `[x, x, x...], [y, y, y...], [z, z, z...]` |
| **ベクトル化 (SIMD)** | 非連続アクセスになり Gather 命令が走り遅い | 連続アドレス（ストライド1）ロードで最速 |
| **キャッシュ効率** | 1つの成分だけが必要な場合も、無駄な成分がロードされる | キャッシュライン（64B）に必要なデータが凝縮される |

### 推奨される実装パターン (C++)

AoSからSoAへの変換時は、成分ごとの配列をヒープから確保し、ループ内では自プロセッサのレジスタ（局所変数）にロードして不変に保ちつつ、内ループで連続アクセスする。

```cpp
// 良い例 (SoA):
#pragma omp parallel for
for (int i = 0; i < N; ++i) {
    // 自粒子のデータはレジスタ（局所変数）に保持
    const double xi = x[i];
    const double yi = y[i];
    
    // 内ループは連続メモリアクセスになり、ベクトルロード(SIMD)が有効になる
    for (int j = 0; j < N; ++j) {
        double dx = x[j] - xi; // x[j]はメモリ上で連続
        double dy = y[j] - yi;
        // 演算...
    }
}
```

## 2. CPU 自動ベクトル化 (SIMD) の促進

コンパイラ（Grace CPUのSVE2やIntel XeonのAVX-512など）が自動でベクトル命令を適用しやすいコードを書く。

1. **ポインタエイリアシングの排除 (`__restrict__`)**:
   - コンパイラは、ポインタ同士のメモリ領域が重複している可能性（エイリアシング）があるとベクトル化を諦める。
   - 計算を行う関数の引数や、配列ポインタに対して `__restrict__` キーワード（または `#pragma ivdep`）を付与し、重複がないことを明示する。
2. **ループ内インバリアント（不変値）の追い出し**:
   - 内ループで不変な計算（特に自スレッド/自粒子に依存する値など）は、必ず外ループ側で計算して局所変数に退避しておく。
3. **ループのストライド（刻み幅）を 1 にする**:
   - 多重ループの場合、最も内側のループがメモリ上で隣接するアドレスを順に参照するようにインデックスの順番を設定する（特に多次元配列での参照順）。

## 3. GPU (OpenACC/CUDA) 最適化: Coalesced Access の実現

GPU上のグローバルメモリアクセスにおいて、同一Warp内の32スレッドが連続するメモリアドレスに同時にアクセス（Coalesced Access）できるようにSoA構造を適用する。

- **非合体アクセス (Uncoalesced Access)** は、GPUカーネルのメモリスループットを著しく低下させる最大の原因となるため、Nsight Compute等のプロファイラで警告された場合は即座にSoA化を計画すること。

## 4. 高速数学オプション (Fast Math) とハードウェア近似の活用

HPCやAI等の数値計算において、IEEE 754 規格の厳密な丸め規則を一部緩和し、プロセッサ固有の高速演算器を最大活用するためのコンパイル最適化手法。

### ① `sqrt()` (平方根) から `rsqrt()` (逆数平方根) への置換
- **数学的背景**: 重力計算や静電相互作用における力 $F \propto \frac{1}{r^2} \frac{\vec{r}}{r} = \frac{\vec{r}}{r^3}$ は、平方根をとったあとに除算するのではなく、逆数平方根の3乗 $\left(\frac{1}{\sqrt{r^2}}\right)^3$ として計算できる。
- **ハードウェアの仕組み (SFU / MUFU)**:
  - GPUの特殊関数ユニット (SFU/MUFU) は、**内蔵ルックアップテーブル (LUT)** で取得した初期近似値に対し、割り算を含まない **Newton-Raphson法 (反復法)** をハードウェア回路レベルで高速実行し、倍精度に引き上げる。
  - x86 (AVX-512) や ARM SVE2 などの現代的CPUにも、同様の逆数平方根近似シード命令（`vrsqrt14pd`, `frsqrte` 等）が存在する。
- **最適化指針**: `1.0 / sqrt(x)` のように記述するか、Fast Math オプションを有効にすることで、ハードウェアの高速な `rsqrt` 命令へ自動置換され、最も重い演算である「除算」と「平方根」を完全に回避する。

### ② Fast Math が有効化する4つの最適化
1. **数学的近似命令への置換**: `sqrt` や除算、超越関数 (`sin`, `cos`, `exp`, `log`) を低レイテンシの近似命令・近似ライブラリへ置換。
2. **結合法則の無視 (Reassociation)**: 浮動小数点の結合法則 $(a + b) + c \neq a + (b + c)$ を緩和し、コンパイラが最も並列ベクトル化しやすい順序でループ加算（リダクション）を行うことを許可。
3. **FTZ (Flush-To-Zero) & DAZ (Denormals-Are-Zero)**: ゼロに近い極小の非正規化数（Denormal）を強制的に `0.0` として扱い、ハードウェア例外（数秒〜数百サイクルレベルの割り込みオーバーヘッド）を回避。
4. **FMA (Fused Multiply-Accumulate) の統合**: 乗算と加算 $a \times b + c$ を途中で丸めずに1命令で処理し、精度と速度を同時に向上。

### ③ 主要コンパイラの Fast Math フラグ
- **NVIDIA HPC SDK (`nvc++`)**: `-gpu=fastmath`
- **Intel oneAPI (`icpx`)**: `-fp-model fast=2` (または `-O3` に内包)
- **GCC / Clang**: `-ffast-math`
