# adversarial-review

## 実行前

1. 対象差分、前提仕様、完了条件、Maker のモデルを確認する。
2. `../../rules/models.md` §2.5 と §3.6–§3.7、
   `../../docs/routing.md` を読み、監査担当・設定・申請要否を決める。
   暫定指示を含め、割当は本書に複製しない。
3. `../../rules/delegation.md` の監査スコープと委譲手順を確認する。
   依頼の追加委譲禁止・API禁止・モデル指定も確認する。
   適合する経路がなければ停止して報告する。

## 監査

1. 呼び出す実際のモデル・経路・設定・監査範囲を事前表示する。
2. 親の会話履歴を渡さず、対象差分・前提仕様・制約を渡す。
   Maker と異種ファミリーのモデルを用い、正本の独立性の条件を確認する。
3. 編集は禁止し、関連ファイルの閲覧・検索を許可する。
4. 各指摘に重要度、根拠箇所、影響、具体的な修正案を求める。
   必要なら境界値テスト案も同じ依頼に含める。
5. 指摘を精査し、blocker / major を修正対象とする。
   採否と理由、未解決事項を報告する。

## 運用

- Maker のセルフレビューを独立監査の代用にしない。
- 毎ターンや stop hook で自動実行しない。
- 監査回数・再監査・引き上げは正本と実行環境の契約に従う。
- 結果の保存は任意。保存先は `inbox/REVIEWS/` または sandbox の `docs/logs/`。
