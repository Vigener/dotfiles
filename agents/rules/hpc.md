# HPC 境界

## 1. 禁止コマンド

- 生の `sbatch` / `qsub`、および Miyabi / Pegasus / Sirius への `ssh` / `scp` / `rsync` は、Cursor hook `hpc-shell-gate` が deny する。
- 必ず `ppx_harness` / `miyabi_harness --dry-run` を経由する。実ログインは人間が行う。

## 2. ジョブ設計

- ジョブスクリプト作成、スケーリング実験計画、クラスタ投入準備の前に、必ずスキル `hpc-job-guardrails`（`~/dotfiles/agents/skills/hpc-job-guardrails/SKILL.md`）を読む。
- その規律（ノード分離・2ノード関門・ログインノード完結・Fail-Fast）を遵守する。

## 3. 計算資源の使い方

- Miyabi の GPU 時間は潤沢である（2026-10 時点で、2027-03 までの枠が 1 万 GPU 時間を超え、使用は 1% 未満。不足したら買い足せる）。節約のために測定を削らない。
- 最初の最小投入テスト（2 ノード関門）に問題がなければ、本投入は論文に使える精度で行う。反復は 3 回平均で済ませず 10 回程度にし、walltime も十分に取る。取り直しの二度手間を避ける。ただし walltime を延ばすとキュー待ちが長くなりうるので、延ばすより、ジョブを分けて同時に投入することを優先する。
- アイドル課金の回避・Fail-Fast・ノード分離の規律は維持する。意味のない大量投入はしない。

## 4. 待ち時間を意識した開発フロー

- 1 ジョブのキュー待ちが長いので、独立したジョブはまとめて同時に投入する。
- 待っている間に、結果の整理・文書化、次の実験の準備、ローカルでのコードの正しさのテスト、人間の理解を進める作業を並行して進める。
- 投入内容は、投入前に `--dry-run` で確認する。実ログインと投入は人間が行う。
