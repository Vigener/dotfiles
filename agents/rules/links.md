# リンク記法・ポータビリティ（2026-10-23 改訂）

T3 Code の右パネルとブラウザで開けることを最優先にする。
T3 Code は、チャット内の相対パスを「スレッドのワークスペース」基準で解決する。
そのため、別リポジトリのファイルを相対パスで書くと、存在しないパスを探して開けない。
絶対パスの Markdown リンクは、ワークスペース外でも開けることを確認済み（2026-10-23）。

## 1. チャット回答文

- ファイルに言及するときは、絶対パスの Markdown リンクを使う。
  - 例: `[RESEARCH_MAP.md](/Users/mikoto/ghq/github.com/Vigener/b4-qcut-workbench/docs/RESEARCH_MAP.md)`
  - 表示名は、ファイル名か短い説明にする。
- 同じリポジトリ内でも、絶対パスにそろえる。相対パスとの混在は、どれが開けるか判断できず危ない。
- `file:///` は書かない。
- ファイルパスを、リンクにせず書かない。バッククォートで囲んだ相対パス（`repo/path`、`docs/foo.md`）も、T3 Code が自動でリンクにし、ワークスペース基準で解決して壊れる。
  - 会話の流れで書くときも、必ずリンクにする。
  - 送信前に、本文中のパス風の文字列がすべて絶対パスのリンクになっているかを確認する。
- ブラウザで開く成果物（HTML 等）は、`http://mikotomac-mini:<port>/...`（tailnet）で示す。

## 2. ファイル内リンク

- リポジトリ内のファイル（`.md` / `.html` 等）に、ホスト固有の絶対パスを書かない。
  - 対象は `file:///Users/...` と `/Users/...`。
  - clone した先や別マシンで壊れ、git の差分にもホスト名が混ざる。
- 同じリポジトリ内は相対パス（`./path/to/file.md`、`../notes/file.md`）または WikiLink（`[[filename]]`）を使う。
- 別リポジトリのファイルは、リンクにせず、リポジトリ名を明記した文で書く。
- この節は、チャットの書き方（§1）とは別のルール。ファイルに書くものは相対、チャットで見せるものは絶対にする。

## 3. 背景

- 以前は Obsidian（SMB 経由で MBA）で開く前提で、チャットでも相対パスにそろえていた。
- 現在は T3 Code の右パネルとブラウザが主なので、チャットでの相対パスをやめた。
- 相対パス・WikiLink を残すのは、ファイル内のリンクだけ。
